# Review-Driven Refactor Skill

> 이 스킬은 `/review` 결과를 입력으로 받아, 리뷰에서 발견된 문제를 자동으로 수정한다.
> 리뷰어가 "여기가 문제다"라고 짚은 것을, 이 스킬이 실제 코드로 고친다.
> 수정은 최소 범위로 한다. 리뷰에서 지적하지 않은 코드는 건드리지 않는다.

## 동작 원칙

1. **리뷰 결과만 수정한다**
   - 리뷰에서 지적된 항목만 고친다
   - "이왕 고치는 김에" 식의 추가 리팩토링은 하지 않는다
   - 리뷰에 없는 코드 개선, 주석 추가, 포맷팅 변경 금지

2. **우선순위를 따른다**
   - 1순위: **수정 필요** (런타임 에러, 보안 취약점, 데이터 무결성)
   - 2순위: **개선 권장** (성능, 설계 개선)
   - 3순위: **검토 필요** (트레이드오프가 있는 항목 — 사용자 확인 후 수정)

3. **한 항목 = 한 커밋 단위**
   - 각 수정 항목은 독립적으로 커밋 가능한 단위로 작업한다
   - 밀접하게 연관된 수정만 하나의 커밋으로 묶는다

4. **기존 아키텍처를 존중한다**
   - `.claude/skills/api-dev/SKILL.md`의 규칙을 따른다
   - 패키지 구조, 네이밍 컨벤션, 레이어 규칙을 준수한다
   - 프로젝트의 CLAUDE.md 규칙을 준수한다

## 워크플로우

### Step 1: 리뷰 결과 파싱

대화 컨텍스트에서 리뷰 결과를 가져온다. 리뷰 결과가 없으면 사용자에게 다음을 안내한다:
- "리뷰 결과가 없습니다. `/review`를 먼저 실행하거나, 수정할 내용을 직접 알려주세요."

리뷰 결과에서 아래 항목을 추출한다:
- **수정 필요**: 즉시 수정해야 하는 버그, 런타임 에러, 보안 문제
- **개선 권장**: 성능, 설계 측면의 개선
- **검토 필요**: 트레이드오프가 있어 개발자 판단이 필요한 항목

### Step 2: 수정 계획 제시

수정 항목을 테이블로 정리하여 사용자에게 보여준다:

```
## 리팩토링 계획

| # | 우선순위 | 대상 파일 | 수정 내용 | 상태 |
|---|---------|----------|----------|------|
| 1 | 수정 필요 | SecurityConfig.java | Map.of() NPE 수정 | 대기 |
| 2 | 수정 필요 | build.gradle | MySQL 드라이버 추가 | 대기 |
| ... | | | | |

### 검토 필요 (사용자 결정 대기)
- [ ] 항목 A: (트레이드오프 설명) → 수정할까요?
- [ ] 항목 B: (트레이드오프 설명) → 수정할까요?
```

사용자가 "전부 진행", "N번 빼고 진행", 또는 개별 선택을 할 수 있도록 한다.

### Step 3: 순차 수정 실행

승인된 항목을 우선순위 순서대로 수정한다. 각 항목마다:

1. **수정 전 파일을 반드시 읽는다** (최신 상태 확인)
2. **최소 범위로 수정한다** (해당 이슈만 고침)
3. **수정 후 검증한다**:
   - 컴파일 에러 없는지 확인 (가능하면 `./gradlew compileJava`)
   - 관련 테스트 통과 확인 (있는 경우)
   - 다른 파일에 영향 없는지 확인
4. **git 명령어를 제안한다**:
   ```
   git add <수정된 파일>
   git commit -m "[fix] SecurityConfig Map.of() NPE 수정"
   ```

### Step 4: 결과 보고

모든 수정이 끝나면 결과를 보고한다:

```
## 리팩토링 결과

| # | 대상 파일 | 수정 내용 | 결과 |
|---|----------|----------|------|
| 1 | SecurityConfig.java | Map.of() NPE 수정 | 완료 |
| 2 | build.gradle | MySQL 드라이버 추가 | 완료 |
| ... | | | |

### 미수정 항목
- (사용자가 보류한 항목 목록)

### 추가 작업 필요
- (수정 중 발견된 추가 이슈, 있는 경우)
```

## 수정 유형별 가이드

### 런타임 에러 수정
- NPE, ClassCastException 등 즉시 에러가 발생하는 코드
- 누락된 의존성, 설정
- 방어 코드 없는 외부 입력 처리
- **검증**: 컴파일 + 가능하면 단위 테스트

### 보안 취약점 수정
- Path Traversal, 입력값 검증 누락
- 하드코딩된 비밀번호/키
- **검증**: 코드 레벨 확인

### 성능 개선
- N+1 쿼리 → JOIN FETCH 또는 @EntityGraph
- 불필요한 객체 생성 → 캐싱 또는 @PostConstruct
- **검증**: 쿼리 변경 시 기존 동작 유지 확인

### 설계 개선
- 누락된 예외 처리 → ErrorCode 추가 + catch 처리
- 누락된 비즈니스 검증 → Service에 검증 로직 추가
- 누락된 Repository 메서드 → 메서드 추가
- **검증**: 기존 API 동작에 영향 없는지 확인

### 연관 데이터 정리
- FK 제약 위반 방지를 위한 삭제 순서 처리
- Repository에 deleteByXxx 메서드 추가
- Service에서 연관 데이터 먼저 삭제
- **검증**: 삭제 흐름 전체 확인

## 수정 시 금지 사항

- 리뷰에서 지적하지 않은 코드 변경
- 기존 API 응답 구조 변경 (하위 호환성 깨짐)
- Entity에 @Setter, @OneToMany, cascade 추가 (프로젝트 규칙 위반)
- 파일 포맷팅만 바꾸는 커밋
- 주석이나 JavaDoc 추가 (요청하지 않은 경우)
- 테스트 코드 생성 (테스트는 /test 스킬로)

## 연계 스킬

- `/review` → `/refactor`: 리뷰 결과를 넘겨받아 수정
- `/refactor` → `/test`: 수정된 코드에 대한 테스트 작성 필요 시
- `/refactor` → `/review`: 수정 후 재검증이 필요한 경우

## 호출 방법

```
# 직전 /review 결과 기반으로 전체 리팩토링
/refactor

# 직전 /review 결과에서 특정 항목만 수정
/refactor 수정 필요 항목만 진행해줘

# 직전 /review 결과에서 SecurityConfig NPE만 수정
/refactor SecurityConfig NPE 수정해줘

# 리뷰 없이 직접 수정 지시
/refactor PostService에서 N+1 쿼리 수정해줘
```
